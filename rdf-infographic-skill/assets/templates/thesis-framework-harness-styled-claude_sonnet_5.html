Synopsis

Two Sources, One Test¶

Circle's “Building the Open Agentic Economy” argues that intelligence is becoming the internet's next foundational building block — software as delegable labor that monetizes its own work, provided agents can discover, install, and pay for services without gatekeepers. It proposes a three-layer Stack (Foundation, Trust Primitives, Capstone) and five principles for trusted discovery.

The x402-buyer skill is a working implementation of exactly the Foundation layer's value-transfer component: a client that fetches a URL, signs a real EIP-3009 authorization when challenged with HTTP 402, and settles against the public Base Sepolia facilitator. This collection doesn't just summarize Circle's thesis — it tests one specific claim against it, using three probes run in the same session that generated this document, one of which completed a genuine, independently-verified on-chain settlement.

The Stack

What an Open Agent Economy Requires¶

Circle's own three-layer status model, in order — existing, emerging, missing.

Foundation existing

  • Identity — ERC-8004 (agentId + agentURI)
  • Value-transfer protocol — x402 / MPP
  • Capability format — OpenAPI / agentURI
  • Settlement — Stablecoins (USDC)

Trust Primitives emerging

  • Reputation — behavior-grounded signals
  • Validation — ERC-8004 + verifiable compute

Capstone missing

  • Trusted discovery — multi-input ranking system

The $9.99 settlement, verified independently

The client reported success with a transaction hash. That claim was not taken at face value: a direct eth_getTransactionReceipt RPC call to the same public Base Sepolia endpoint the skill defaults to confirmed status 0x1, a matching ERC-20 Transfer event, and the exact settled amount — buyer 0x0102257D…2ab553 to seller 0xb410b5E8…1200C79, tx 0x2efb8442…90f4144.

What the article doesn't mention: port 5443

WebID-TLS/NetID-TLS on these resource servers lives on port 5443, not 443 — port 443 never issues a CertificateRequest, so it falls straight through to a misleading 401 regardless of certificate availability. A naive first attempt at reaching a Foundation-layer resource would conclude, wrongly, that it has no payment layer at all. Confirmed identical behavior on two independent hosts, and generalized into both x402-buyer and acp-client as an automatic default the same session.

HowTo

Validating a Foundation-Layer Claim Empirically¶

1

Probe the plain HTTPS URL first

A 401 with WWW-Authenticate: Digest on port 443 is NOT proof the resource lacks an x402 layer.

2

Retry with WebID-TLS on port 5443

This is where the CertificateRequest is actually issued; x402-buyer automates the port rewrite.

3

Follow any redirect, presenting the cert on every hop

Some resources 302-redirect through a ?k=... capability URL before the real 402; others answer directly.

4

Decode the PAYMENT-REQUIRED header before acting

Base64-decode the challenge to see the amount, network, and pay-to address before any signing happens.

5

Sign and settle with the buyer client

Run x402-buyer's scripts/x402_get.py, which signs a real EIP-3009 authorization.

6

Verify the settlement independently

Query the same public RPC endpoint directly for the transaction receipt — never rely on the client's self-report alone.

Glossary

Terms¶

x402

A payment protocol activating HTTP's reserved 402 status code for per-request stablecoin settlement.

MPP

Machine/Monetary Payment Protocol — x402's sibling protocol family in Circle's Foundation layer.

USDC

Circle's US-dollar-pegged stablecoin, the dominant settlement asset in x402 transactions.

ERC-8004

An Ethereum Improvement Proposal defining a Trustless Agents identity standard and trust registries.

WebID-TLS

A mutual-TLS protocol binding a client certificate to a WebID; on OpenLink servers, lives on port 5443.

NetID-TLS

Alias/successor naming for WebID-TLS used interchangeably — same underlying mTLS mechanism.

Facilitator

The third party that verifies and settles a presented x402 payment authorization on-chain.

EIP-3009

An Ethereum token-transfer authorization standard the x402-buyer skill signs to authorize settlement.

Permit2 / EIP-2612

A gasless-approval mechanism some x402 challenges advertise as an extension.

PAYMENT-REQUIRED header

The base64-encoded HTTP header carrying an x402 challenge's accepts[] options.

Base Sepolia

The Ethereum Layer-2 testnet this session's x402 probes and settlement ran against.

Stranger test

Circle's bar for its Full Loop milestone: a transaction between parties with no prior relationship.
