# Weblog From WebDAV

Turn a Virtuoso WebDAV collection of HTML or Markdown documents into a working weblog — feeds, search, categories, pinning, a password-protected admin dashboard, and an optional email newsletter — with no separate CMS or database.

## Overview

Point this skill at a WebDAV collection full of posts and it generates a self-contained `index.vsp` (the public weblog) plus a separate, non-public admin dashboard. Everything else — look and feel, the newsletter, category tags, pinned posts — is a **configuration modality**: a property you set on the collection, read at request time, changeable without a redeploy.

For the full technical reference (deploy modes, identity/auth options, VSP internals, gotchas found in production), see `SKILL.md`. This file covers the user-facing features.

## Quick Start

```sql
SELECT DB.DBA.WEBLOG_DAV_DEPLOY_SKINNED (
  '/DAV/home/dba/my-weblog/',   -- WebDAV collection of posts
  '/weblog/',                   -- public route
  'My Weblog',                  -- title
  'A weblog powered by WebDAV.',-- tagline
  'classic',                    -- skin: 'classic' or 'editorial'
  'dba'                         -- account that owns the deployment
);
```

Run via `templates/deploy-weblog-skinned.sql`, or `templates/upgrade.sql` for a single-file install/upgrade that also sets up the newsletter tables and an operator role. Re-running either is always safe — see **Upgrades are never destructive**, below.

## Modalities

### Skins

Two built-in looks, switchable per request (`?skin=editorial`) or per collection (`weblog:skin` property) — no redeploy needed:

- **classic** — sidebar archive + search/filter, a single embedded post.
- **editorial** — a large single-column hero post with a card-grid archive below.

Add a skin from the admin dashboard's Skin setting at any time.

### Admin dashboard

A separate, non-public collection (never inside the public blog folder, so it never inherits whatever makes the blog itself public) serves a password-protected dashboard: subscriber list, digest scheduling, skin/newsletter settings, category tagging, and post pinning. Access is native HTTP Digest authentication against real Virtuoso accounts — no shared secrets, no tokens embedded in a page.

### Newsletter

Double opt-in email subscription, sent through the operator's own SMTP relay:

1. Enable it: `weblog:newsletterEnabled = 'true'` (or the dashboard's toggle).
2. A **Subscribe** button appears next to RSS/Atom, opening an in-page dialog — visitors never leave the article they're reading.
3. New subscribers confirm by email before being added; digests (or immediate per-post sends) go out on a schedule you control from the dashboard.
4. Manual entry, CSV import, and RDF (`schema:Person`) import are all available from the dashboard for migrating an existing list.

Requires `templates/register-weblog-newsletter.sql` in addition to the base deploy.

### WebDAV Permalink

Every post view shows a **WebDAV Permalink** — the post's real, absolute URL on the underlying WebDAV collection — separate from the weblog's own `?post=` view URL. Useful for citing or bookmarking the actual resource rather than a query-string view of it.

### Feeds

RSS 2.0, Atom 1.0, and AtomPub are generated automatically from the same post list the weblog itself renders — no separate feed file to keep in sync.

### Category tags and pinning

Posts can carry a `schema:category` tag (shown as a filterable facet in the sidebar) and a pin (`schema:position`) to feature a post ahead of normal recency — both editable from the admin dashboard, or via `templates/register-weblog-pinning-tool.sql` for agent-driven pinning.

## Upgrades are never destructive

Re-running a deploy or `upgrade.sql` against an already-deployed collection is always safe: it recognizes its own prior output and refreshes it in place, preserving every `weblog:*` setting (skin choice, newsletter config, admin email, and so on). If a collection's `index.vsp` was **not** generated by this skill — for example, an unrelated, hand-authored page happens to sit at that path — the deploy refuses to touch it rather than guessing, with a clear message pointing at the admin dashboard's Skin setting for changes that don't need a redeploy at all.

## Requirements

- A Virtuoso Server instance with WebDAV enabled and `isql` access (plain SQL, or WebID-TLS/mTLS).
- A WebDAV collection containing HTML or Markdown posts.
- For the newsletter: an SMTP relay reachable from the Virtuoso instance (`weblog:newsletterSmtpServer`, or the server's own default mail configuration).

## Limitations

- One admin identity model per collection: the account in `weblog:adminDavUser`, plus members of the `WEBLOG_OPERATOR` role, plus `dba`.
- The newsletter's "immediate" and "digest" send modes cover most cases, but there is no per-subscriber send-time customization.
- Feed and search results are scoped to the single WebDAV collection being served — this is not a multi-collection aggregator.
